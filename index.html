Charge for the routes of your Express API that are worth paying for.

LicenRoute puts licence keys, usage quotas and revocation in front of the routes you choose — reports, data, exports — while login, public pages and health checks keep working exactly as before. You, or your AI coding assistant, set it up in minutes. Nothing is written until a human approves.

The problem

Your API is all-or-nothing

Some of your routes are valuable. Today they are either public — scraped by anyone, including AI crawlers — or locked behind your own login. Building API keys, quotas, metering and revocation yourself takes weeks, and one mistake in the middleware either blocks your users or gives everything away.

Paid access per route

Sell a package of requests for /api/reports/** without touching /login or /health.

Licences you can revoke

Invented keys get 403. Revoke one and the next request is refused — no redeploy.

Safe when things fail

If the decision service is down, paid routes close (503) and public routes stay up. Nothing is served for free by accident.

How it works

From your code to paid routes in four steps

The CLI reads your Express app without running it, proposes what to protect, and only writes the exact change a person approved.

1

Detect

Static analysis of Express 4/5 — JS or TS, ESM or CommonJS, routers mounted with app.use. Finds health checks, login, public and already-authenticated routes.

2

Plan

Plans per route prefix and HTTP method (GET+HEAD; OPTIONS is never charged). Login, health and writes are never proposed — they are listed for your decision.

3

Approve

You see the full diff. To write it, a person types a one-time challenge on the terminal. Node's permission model is a second barrier.

4

Test & undo

licenroute test checks every case against a local simulator. licenroute undo restores your files byte for byte.

Built for AI

Made to be integrated by AI assistants — and consumed by AI agents

Your coding assistant prepares, you approve

Run licenroute assistant . --claude-code (or --cursor) to install a Skill or rules that teach the safe flow detect → plan → preview → your approval → test → undo, plus a hook that:

  • asks you before any LicenRoute write
  • blocks the assistant from reading .env* files
  • denies approval shortcuts and package runners like npx

The assistant can do everything except type the challenge. The CLI asks for it on your terminal.

Agents get a machine-readable answer

A program calling a licensed route without a licence does not just get an error page. It gets JSON that says how to unlock the route:

# GET /api/reports  (no licence)
HTTP/1.1 402 Payment Required
{
  "error": "payment_required",
  "request_id": "01a1…",
  "payment": {
    "plan_id": "api-reports",
    "checkout_url": "https://…/checkout/api-reports",
    "currency": "EUR",
    "unit_price_minor": 150,
    "unit_size": 1000
  }
}
# then: Authorization: Bearer bgat_…

In demo mode the checkout link points to the local simulator. Example values.

Try it

See it work on the example API in 5 minutes

Requirements: Node.js 24+, npm and git (and script from util-linux on Linux). No account, no Docker.

git clone https://github.com/licenroute/licenroute.git licenroute && cd licenroute
npm ci --ignore-scripts      # dev dependencies from the public npm registry
npm run build                # builds the CLI and SDK packages + SHA256SUMS
./demo/demo.sh               # read-only: shows the plans and the exact diff

Then follow the 10-minute tutorial to approve the integration, start the simulator and run licenroute test. Prefer prebuilt packages? Download them from the v0.3.1-preview release and check them against SHA256SUMS.

Never run npx licenroute. The packages are not published on npm and the unscoped name there is not this project. Install only the .tgz files you built or verified.

Honest status

What works today, and what doesn't yet

Works in the preview

  • Express 4 and 5, JS and TS, ESM and CommonJS
  • Static analysis, plans per route and method
  • Approval bound to the exact diff, exact undo
  • Local simulator: licences, quotas, revocation, outage and recovery
  • Claude Code and Cursor integration; English and Spanish
  • Validated on macOS (Apple silicon) and Ubuntu 24.04 x86_64

Not yet

  • No hosted service: no real licences, billing or payments
  • Not reviewed for production traffic; no external security audit
  • Not on npm (names under @licenroute are provisional)
  • Rails can be analysed but not integrated; Windows not tested

FAQ

Questions developers ask

How do I add API keys and usage quotas to an existing Express API?

Install the CLI and the Express SDK from the verified packages, run ./node_modules/.bin/licenroute init . to see the proposed plans, preview the diff with --plans, and approve it with --write --approve apr_… plus the challenge typed in your terminal. The tutorial walks through it.

Can I sell usage in packages, per request?

Yes, that is the model: each plan has a quota (for example 1,000 requests) and a price per package. GET and HEAD share the quota; OPTIONS is never charged. In the preview everything runs against the simulator, so nothing is actually charged.

Is it safe to let an AI coding assistant set it up?

That is what it was designed for. The assistant can detect, plan, preview and test, but writing requires a person to type a one-time challenge on the controlling terminal. The included hook also blocks reading .env files and approval shortcuts. The challenge proves someone typed it there, not who.

What happens to my login, health checks and public pages?

They are never proposed for licensing. LicenRoute lists them as "left untouched" or "needs your decision", and licenroute test checks that public routes keep answering 200.

What if the licence service is down?

Licensed routes fail closed with 503 — even if your app starts while the service is unreachable — and public routes keep working. The test suite simulates an outage and the recovery.

How is this different from an API gateway or a rate limiter?

LicenRoute lives inside your Express app as middleware, declared per route and HTTP method, so a POST with its own authentication under the same prefix is left alone. It sells and enforces licences with quotas; it is not a proxy in front of your whole API.

Is it production-ready? Is there a hosted service?

No and not yet. This is a developer preview in demo mode. If you would use a hosted version that issues real licences and handles payments, tell us what you need.

Have an Express API with routes worth paying for?

Try the preview, and tell us what's missing. A hosted service is the next step if developers need it.
